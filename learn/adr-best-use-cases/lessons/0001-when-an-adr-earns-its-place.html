Your win today: identify a decision worth recording, explain why, and leave with a proposed practice ADR. ADR means Architecture Decision Record.

Practice context

These examples borrow workers and image storage from the existing Image Horse learning track. The constraints below are hypothetical. They do not describe choices already made or shipped in Image Horse.

Before you start, say aloud: have you written an ADR, reviewed one, or only heard the term? If you already use them, focus on the borderline cases and explain what evidence would change your answer.

1. Save the reason that code cannot tell you

Code reveals the implementation. An ADR preserves the context and tradeoffs behind an architectural choice. That distinction is central to the ADR community’s definition.

A practical decision aid for this lesson—not a mandatory industry checklist.
AskAn ADR is useful when…
What does this constrain?Ownership, interfaces, data compatibility, or an important quality such as recoverability.
Why might someone undo it?The obvious alternative is attractive, but a non-obvious tradeoff ruled it out.
Where will the reason be needed?Across later changes, onboarding, or a future replacement decision.
Is the reason already sufficient in the PR?A routine correction usually needs no separate architectural record.

Michael Nygard’s original article focuses on architecturally significant decisions. Diff size is a poor proxy. A one-line durability setting can change the product’s guarantees; a thousand formatting changes may change none.

“Use a PR” is our application of that significance test, not a ban on documenting small changes. Likewise, adding a dependency is a reason to investigate the tradeoff, not proof that every package needs an ADR.

Write a short reason, then choose. Feedback checks the choice; compare its explanation with yours. The browser does not grade your reasoning.

  1. The image engine will move to a worker. It will own mutable image state, while the UI sends commands and receives results. Keeping it on the main thread was considered.

  2. A button says “Dowload.” You correct it to “Download.” Its behavior and accessibility name otherwise remain equivalent.

  3. You replace the saved-project format. New saves will require a migration path, and older app versions will not open them. You choose this over maintaining the old format indefinitely.

  4. An existing formatter changes indentation in 120 files. You are applying the already agreed configuration, with no semantic or policy changes.

  5. A teammate says, “I added a library.” You have no information about its role, runtime use, data model, or replacement cost.

  6. A one-line setting makes saving faster by allowing the most recent acknowledged edits to be lost after a crash. The team is deliberately accepting that tradeoff.

3. Write the reason, including the cost

Pick one ADR-worthy scenario above, or use your own decision. Complete the five fields below. Keep the whole record short enough that someone will actually read it.

A proposed decision is awaiting agreement. Acceptance follows your project’s review process. When an accepted decision is replaced, preserve it and link its successor. See the AWS ADR process.

This exercise adds a separate alternatives field to make your reasoning visible; it is not a mandatory section of Nygard’s original template. Your local ADR skill also has its own format and acceptance rules. Use those when creating a real project record.

PartExample


ContextAssume a reproduced synchronous export blocks pointer handling. The UI must remain responsive during export.


DecisionPropose worker ownership of the image engine, with explicit commands and results between worker and UI.


BenefitEngine execution no longer directly occupies the UI thread. Measure end-to-end input latency before accepting this proposal.


CostWe must handle asynchronous failures, message ordering, and the cost of transferring or copying image data.


AlternativeKeep the engine on the UI thread and split export into short tasks. In this scenario, reject it because the synchronous export cannot be divided without redesigning the engine.
