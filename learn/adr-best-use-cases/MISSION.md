# Mission: ADR Best Use Cases

## Why

Choose which engineering decisions deserve a lasting explanation, so future maintainers can understand the tradeoffs without reopening every discussion. Turn that judgment into one useful proposed Architecture Decision Record (ADR).

This is the working interpretation of Chris's requested topic, “ADR Best Use Cases.” Image Horse-style worker and storage scenarios provide familiar practice; they are hypothetical, not claims about current implementation or accepted decisions.

## Success looks like

- Distinguish an architectural choice from a routine change and explain when a PR description is enough.
- Identify the constraint, rejected alternative, and real cost behind a decision.
- Draft one proposed practice ADR that a future maintainer can understand.
- Explain how new evidence can replace a decision while preserving its history.

## Constraints

- One short lesson, approximately **20 minutes**, with classification practice and a small writing exercise.
- Tables for comparisons; short prose for causal reasoning.
- Ground the guidance in primary sources and distinguish project conventions from general practice.
- Prior ADR experience is unassessed. Adjust difficulty based on Chris's answers.

## Out of scope

- Backfilling real project ADRs or approving an architectural choice.
- Changing Image Horse code or its documentation policy.
- Designing an organization-wide governance process.
